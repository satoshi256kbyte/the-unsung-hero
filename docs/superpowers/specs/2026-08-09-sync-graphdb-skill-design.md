# sync-graphdb スキル設計

## 目的

プロジェクトの docs/ およびソースコードを読み取り、
Neo4j にナレッジグラフとして反映するスキル。
AIエージェントが設計・コードを理解するためのコンテキスト供給源として機能する。

## 実行方法

| 方法 | トリガー |
|------|---------|
| 手動 | `/sync-graphdb` コマンドまたはキーワード |
| 自動 | Stop hook（ターン終了時、変更があった場合のみ） |

手動トリガーキーワード:
「graphdb更新」「ナレッジ同期」「グラフDB反映」「Neo4jに入れて」など。

## 処理フロー

### 1. コンテナ起動確認

`docker compose ps` でNeo4jコンテナの状態を確認する。
停止中であれば `docker compose up -d` で起動し、
Bolt接続（7687）が応答するまで待機する。

### 2. 現在のグラフ状態確認

`read_neo4j_cypher` でNeo4jの現在の状態を取得する。

- ノード数
- ラベル一覧
- リレーションシップタイプ一覧

初回実行時（ノード数0）は全リビルドとして扱う。

### 3. プロジェクトコンテンツの読み取り

docs/ 配下のMarkdownファイルおよびソースコード（存在する場合）を読み取る。

### 4. 更新戦略の判断

Claude自身が変更規模とグラフの現状を見て判断する。

| 判断 | 条件（目安） | 操作 |
|------|-------------|------|
| 全リビルド | 初回、構造の大幅変更、データモデル見直しが必要 | `MATCH (n) DETACH DELETE n` → 全再構築 |
| 差分更新 | 既存ノードの内容修正、小規模な追加・削除 | 対象ノード/エッジのみ更新 |

判断基準は固定しない。コンテンツの変化量とグラフの整合性を見てClaude自身が決定する。

### 5. Cypherクエリの投入

`write_neo4j_cypher` でグラフを更新する。

データモデル（ノードラベル、プロパティ、リレーションシップタイプ）は
スキル実行時にClaude自身がコンテンツに応じて設計する。
固定スキーマは定めない。

## Stop hook

`.claude/settings.json` に prompt type の Stop hook を追加する。

hookの役割:

1. このターンで docs/ またはソースコードに変更があったか判定
2. 変更があった場合のみ `/sync-graphdb` を実行
3. 変更がなければ何もしない

Neo4jコンテナが停止中の場合はスキル内で起動する（hook側では起動しない）。

## CLAUDE.md

プロジェクトルートに `CLAUDE.md` を作成し、以下を記載する:

- 設計・コードの内容を確認する際は、まずMCP経由でNeo4jグラフDBを参照すること
- グラフDBのデータを活用してプロジェクトのコンテキストを得ること
- Neo4jコンテナが停止中の場合は `docker compose up -d` で起動してからMCPを使うこと

## ファイル構成

| ファイル | 操作 |
|---------|------|
| `.claude/skills/sync-graphdb/SKILL.md` | 新規作成 |
| `.claude/settings.json` | Stop hook を追記 |
| `CLAUDE.md` | 新規作成 |

## 前提条件

- Docker / Docker Compose が利用可能
- Neo4j MCPサーバーが `.mcp.json` に設定済み
- Neo4jコンテナのイメージが pull 済み（初回は pull が走る）
