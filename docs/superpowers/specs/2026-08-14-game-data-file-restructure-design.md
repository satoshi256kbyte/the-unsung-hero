# カード・イベント・ステージのファイル構造再編設計

## 概要

現状、カードのコスト・効果ロジック、ランダムイベントの発生確率・効果ロジックは
それぞれ `constants.ts`（データ定義）と `card.ts`/`event.ts`（switch文によるロジック）に
一括で集約されている。ステージは `src/game/stages/pocStage.ts` の1ファイルのみ存在する。

これを「1カードで1ファイル」「1イベントで1ファイル」「1ステージで1ファイル」という構造に
再編する。ステージが増える＝ファイルが増える、カード・イベントを追加する＝ファイルを1つ
追加するだけで完結する、という構造にすることで今後のゲーム設計を容易にする。

ドキュメント（`docs/`）側も同様の単位で分割し、人手によるバランス調整をしやすくする。
ドキュメントとソースコードでファイルの粒度を合わせるが、フォルダ・ファイル名は
ソースコードは英語（ローマ字）、ドキュメントは日本語とする。

ファイルを分けることでフォーマット変更時の影響範囲は広がるが、
「ステージ／カード／イベントを増やす＝ファイルを増やす」という単純さのメリットが上回るため
この方針を採用する。

## 現状分析

### カード

`CardName` は25種類定義されているが、`card.ts` のswitch文で実際に効果ロジックを持つのは
6種類（デイリー・レビュー・モニタリング・個別面談・表彰・計画休）のみ。
残り19種は現状 `default: break;` で何もしない（未実装）。
コストは `constants.ts` の `CARD_COSTS: Record<CardName, number>` に一括定義されている。

### ランダムイベント

`constants.ts` の `EVENT_PROB` に15種類の基本確率＋6種類のカード使用時の派生確率
（例：レビュー使用時のREWORK確率低下）が定義されているが、`event.ts` の
`rollRandomEvents` で実装済みなのは5種類（stall・rework・sick・low_motivation・fatigue）のみ。

`applyEventToProgress` / `applyEventToMember` は特定のイベント種別に紐づかない
汎用の適用処理（`event.id` の文字列プレフィックス判定、`params.moraleDelta` 等の
汎用パラメータキー判定）であり、イベント種別ごとのロジックではない。

### 条件付きイベント

`conditional.ts` の `evaluateCondition` は条件式文字列（例: `"turn >= 5"`）を解析する
共通エンジンであり、各ステージファイルに埋め込まれた `conditionalEvents` 配列の定義を
解釈するための共通処理。イベント種別ごとのロジックではないため分割対象外。

### ステージ

`pocStage.ts` というファイル名は「唯一のPoCステージ」であるかのように読めるが、
実際には「PoC」は難易度・規模の分類であり、同分類の複数ステージが将来追加されうる。
ファイル名を分類の識別子として使うのは誤解を招く。

## ソースコード側の再編

### ソースコードのフォルダ構成

```text
src/game/
  cards/
    daily.ts, review.ts, ...（カードごとに1ファイル、25ファイル）
    index.ts（レジストリ）
  events/
    stall.ts, rework.ts, ...（イベント種別ごとに1ファイル）
    index.ts（レジストリ＋rollRandomEvents集約、汎用適用処理）
  stages/
    poc-01.ts（旧pocStage.ts）
    index.ts（レジストリ）
  conditional.ts（変更なし）
  constants.ts（カード・イベント固有値を除いた横断的なバランス値のみ）
```

### カードモジュール

各カードファイルは以下の形の定義をエクスポートする。

```typescript
export interface CardDefinition {
  readonly cost: number;
  applyEffect(state: GameState): {
    effectsToAdd: CardEffect[];
    memberUpdates: MemberUpdate[];
  };
}
```

`CardName` は現行どおり `types.ts` に明示的なunion型として残す
（カード名の一覧をひと目で確認できるようにするため）。
`cards/index.ts` のレジストリは `satisfies Record<CardName, CardDefinition>` を用いて、
「`CardName` に追加したが対応ファイルを作り忘れる」をコンパイルエラーで検知できるようにする。

未実装（現状switch文で何もしない）19種のカードについても、
コストのみを持ち `applyEffect` が空の結果を返すファイルとして作成し、
実装済み6種と同じ構造に揃える。

`card.ts` は `cards/index.ts` に統合し、`applyCards` はレジストリを走査する形に変える。

### イベントモジュール

各ランダムイベントファイルは以下の形の定義をエクスポートする。

```typescript
export interface EventDefinition {
  roll(state: GameState, activeEffects: CardEffect[]): GameEvent | null;
}
```

カード効果による確率補正（`calcEventProbModifier`）が必要なイベントは、
ファイル内部で基本確率・補正対象の `effectType` を保持して判定する。
判定方法をイベントごとに変える柔軟性を優先し、共通データ形状には固めない。

未実装（現状 `EVENT_PROB` に確率だけ定義されロジックがない）イベント種別も、
基本確率のみを持ち常に `null` を返すファイルとして作成し、構造を揃える。

`applyEventToProgress` / `applyEventToMember` はイベント種別に依存しない汎用処理のため、
`events/index.ts` に共通関数として残す。

`event.ts` は `events/index.ts` に統合する。

### ステージモジュール

ファイル名は「タイプ＋連番」のフラット構成とする（例: `stages/poc-01.ts`）。
`StageData.id` もファイル名と同じ文字列（`"poc-01"`）に変更する。

`stages/index.ts` にレジストリ（`id` → `StageData` のマップ）を作り、
ステージセレクト画面など複数ステージを列挙する箇所から参照できるようにする。

`pocStage.ts` → `poc-01.ts` にリネームし、既存のインポート元
（`MainScene.ts` 等）を更新する。

## ドキュメント側の再編

### ドキュメントのフォルダ構成

```text
docs/03-詳細設計/
  カード.md（横断的な説明のみ残す：適用方式、未決定事項など）
  カード/
    デイリー.md, レビュー.md, ...（既存の表の行ごとに1ファイル、約26件）
  イベント.md（横断的な説明のみ残す：分類、カテゴリ、リスクグラフ、固定イベント、
              手戻り・停滞、未決定事項）
  イベント/
    追加要望.md, 手戻り.md, ...（プロジェクト7＋タスク9＋メンバー7、約23件）
  ステージ/
    PoCステージ01.md（新規）
```

`カード/` `イベント/` `ステージ/` の配下に一覧・索引用のファイルは作らない
（フォルダの中身がそのまま一覧になるため）。

### カード・イベント個別ファイル

既存の `カード.md` `イベント.md` の表の該当行の内容（効果・適用方式・コスト（仮）・説明、
または効果・種別・カテゴリ・説明）をそのまま個別ファイルに分割する。新規の内容追加はしない。

### ステージ個別ファイル（新規）

`PoCステージ01.md` は今回新規作成する。コード側とファイル名の対応が
（ローマ字のid ↔ 日本語ファイル名で）一致しないため、冒頭に対応関係を明記する。

```markdown
# PoCステージ01

**ステージID**: `poc-01`（`src/game/stages/poc-01.ts` に対応）
```

続けて以下2つの表を記載する。

**ガントチャート**（`poc-01.ts` の `initialGantt` を転記。人間が編集して調整する前提）

| タスクID | タスク名 | 工程 | 開始ターン | 期間 | 担当 | 依存タスク |
| -------- | -------- | ---- | ---------- | ---- | ---- | ---------- |
| t01 | 要件定義 | 要件定義 | 1 | 3 | アリス | なし |
| ... | ... | ... | ... | ... | ... | ... |

**ターンごとの条件付きイベント**（`poc-01.ts` の `conditionalEvents` を転記）

| ターン | 発生イベント | 条件 |
| ------ | ------------ | ---- |
| 5 | 中間チェック：進捗が遅れています | `turn >= 5` |
| ... | ... | ... |

担当メンバーは `assignedMemberId`（`alice` 等）を初期メンバー一覧の名前
（アリス等）に変換して記載する。

ステージ構成の一般論（ステージの位置づけ、難易度カーブの考え方等）は
既存の `01-要件定義/index.md` に既に記載されているため重複させない。
`ステージ/` 配下には横断的な概要ファイルを作らない。

## 移行方針

- カード・イベントのドキュメント分割は既存内容の転記のみ。内容の追加・修正はしない
- ステージドキュメント（`PoCステージ01.md`）は新規作成。ソースコードの実データをそのまま転記する
- ソースコード側は既存のswitch文の中身をそのまま各ファイルに移し、未実装分はコスト／確率のみの
  スタブとする。ロジックの新規実装は行わない
- 影響を受ける既存ファイル：`card.ts` `event.ts`（削除・統合）、`constants.ts`（カード・イベント
  固有値を除去）、`pocStage.ts`（リネーム）、`engine.ts` `turn.ts` `MainScene.ts` `CardSlot.ts`
  `MainGameUI.ts`（インポート元の変更）
- 既存の単体テスト（`tests/unit/card.test.ts` `event.test.ts`）の再編方針は別途検討する
  （本ドキュメントのスコープ外）
