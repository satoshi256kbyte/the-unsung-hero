# 技術スタック

詳細な選定理由・ADRはNeo4jグラフDBを参照。

## 構成概要

| カテゴリ | ツール |
| -------- | ------ |
| ゲームエンジン | Phaser 3 |
| 言語 | TypeScript |
| ビルド | Vite |
| Lint/Format | Biome |
| ユニット・プロパティテスト | Vitest + fast-check |
| E2Eテスト | Playwright（ヘッドレス） |
| SCA | Dependabot + npm audit |
| SAST | CodeQL（パブリックリポジトリは無料） |
| 著作権チェック | license-checker-rseidelsohn |
| CI/CD | GitHub Actions |
| ホスティング | AWS Amplify（静的配信） |
| 実装手法 | Spec-Driven Development（SDD）+ Spec Kit |

## アーキテクチャ方針

ゲームロジックとPhaser3描画を分離する。

```text
src/
  game/    ← ゲームロジック（Phaserに非依存・テスト対象）
  scenes/  ← Phaser3 Scene（描画・入力ハンドリング）
  ui/      ← DOM overlay（カード選択UI等・PlaywrightのE2E対象）
```

カード選択UIはPhaser canvasの上にDOM overlayとして配置し、
PlaywrightからDOM操作としてE2Eテストできる構造にする。

## Spec-Driven Development（SDD）

GitHub製の [Spec Kit](https://github.com/github/spec-kit) を使って実装を進める。
仕様（what/why）を先に固めてからコードを生成するアプローチ。

```bash
# Spec Kit CLIのインストール（要: uv）
uv tool install specify-cli

# プロジェクト初期化（Claude Code向け）
specify init . --integration claude
```

主なワークフロー:

1. `/speckit-constitution` — プロジェクト原則の作成
2. `/speckit-specify` — 機能要件の定義（what/why）
3. `/speckit-plan` — 技術実装計画の作成
4. `/speckit-tasks` — タスク一覧の生成
5. `/speckit-implement` — タスク実行・コード生成

## ローカル開発

```bash
npm run dev          # devサーバー起動 → http://localhost:5173
npm run check        # lint + format
npm test             # ユニット・プロパティテスト
npm run test:e2e     # E2E（devサーバー自動起動）
```
