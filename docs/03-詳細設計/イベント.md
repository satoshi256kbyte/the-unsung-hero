# イベント

## 分類

イベントは発生メカニズムの異なる3種類に分類される。

| 分類 | 説明 |
| ------ | ------ |
| 固定イベント | タイミングが確定しており、必ず発生するチェックポイント |
| 条件付きイベント | ステージデータに事前定義。指定ターンに条件を評価し、満たせば発生、満たさなければ永久に消滅 |
| ランダムイベント | 毎ターンのリスクグラフ確率に基づく抽選で発生 |

さらに系統として3つに分かれ、それぞれポジティブ・ネガティブが存在する。

- プロジェクトイベント（例: 追加要望）
- タスクイベント（例: 手戻り）
- メンバーイベント（例: 休み、離脱）

カードを使うことで、固定イベントの回避・発生確定や、ランダムイベントの発生確率の上昇・低下、
メンバーのステータス変動を起こせる。
また、条件付きイベントの発生条件にはカードの使用有無も含まれるため、
カードの選択が条件付きイベントの回避・誘発に間接的に影響する。
カード個別の効果は [カード](./カード.md) を参照。

ポジティブイベントは意図的に数を絞る（現実でもそう頻繁には起きないため）。

## イベントカテゴリ（ガントチャート計算との対応）

種別（ポジティブ／ネガティブ）や3系統の分類とは別に、
イベントには「ガントチャート計算に加味するかどうか」を示すカテゴリを付与する。
次の「発生確率の可視化（リスクグラフ）」で表示するカテゴリは、このカテゴリと同一のものを使う。

ターン切り替え時に発生するガントチャート計算（進捗の反映）に加味するランダムイベントは、
「進捗ダウン」「進捗アップ」の2カテゴリに属するものだけとする。それ以外のカテゴリは、
ガントチャート計算以外の処理（メンバーの稼働判定、コスト集計、確率補正など）と結び付く。

| カテゴリ | 意味 | ガントチャート計算への反映 |
| --------- | ------ | -------------------------- |
| 進捗ダウン | 対象タスクの進捗を下げる、または進捗の増加を止める | あり |
| 進捗アップ | 対象タスクの進捗を通常より押し上げる | あり |
| メンバー稼働系 | 対象メンバーが稼働できるかどうか・稼働人数が変わる | なし（[ターン処理フロー](./ターン処理フロー.md) のメンバー行動確定で、稼働不可のメンバーはダイスを振らない、という形で間接的に進捗へ影響する） |
| スコープ変化系 | ガントチャート上のタスクそのものが増減する | なし（構造変更であり、進捗率の計算とは別に扱う） |
| バフ系 | 確率やパラメータ変化率を一時的に改善する持続効果 | なし（進捗ダウン／アップの発生しやすさを間接的に下げる） |
| デバフ系 | 確率やパラメータ変化率を一時的に悪化させる持続効果 | なし（進捗ダウン／アップの発生しやすさを間接的に上げる、またはコスト・パラメータへ直接作用する） |

各イベント表の「カテゴリ」列に、該当する場合のみ上記を記載する。
空欄は現時点で未分類を意味する。

## 発生確率の可視化（リスクグラフ）

ランダムイベントの発生確率は、「イベントカテゴリ（ガントチャート計算との対応）」で定義したカテゴリ
（進捗ダウン・進捗アップ・メンバー稼働系・バフ系・デバフ系）に分解し、
レーダーチャート（N角形）でPM（プレイヤー）が常時確認できるようにする。
カテゴリ軸はイベントカテゴリと同一であり、リスクグラフ専用の別カテゴリは持たない。
スコープ変化系は条件付きイベントに移行したため、リスクグラフの軸からは除外する。

- 現在時点のスナップショット表示であり、時系列の推移は表示しない
- ガント／PERT／EVMと同様、表示専用（直接操作はできない）
- 各カテゴリと個別イベントの対応関係は、各イベント表の「カテゴリ」列を参照
- 具体的な確率の算出方法は今後詰める

デイリー・レビュー・モニタリング・サマライズなどのカードは、
それぞれが確率を下げる対象イベントのカテゴリを通じてリスクグラフに反映される。
1枚のカードの効果が複数カテゴリにまたがることもある
（例: モニタリングは検収不合格・過大報告・過小報告・報告漏れを対象とするため、
進捗ダウン・進捗アップ・未分類のイベントにまたがる）。
カードとカテゴリの対応は1対1ではない点に注意する。

## 条件付きイベント

ステージデータ（レベルデータ）に事前定義されるイベント。
指定ターンに条件式を評価し、条件を満たせば発生、満たさなければ永久に消滅する。

### 対象イベント

以下のイベントは条件付きイベントとしてステージデータに定義される。
ランダム抽選では発生しない。

- プロジェクトイベント: 追加要望、仕様変更、値下げ要求、監査対応、検収不合格、追加予算承認、早期検収
- メンバーイベント: 離脱、応援要員

### 判定ルール

- 判定は指定ターンのみ実施する。条件を満たさなければそのイベントは永久に消滅する
- プレイヤーには条件付きイベントの存在・条件・タイミングは一切公開されない。
  発生して初めてわかる
- 条件付きイベントはリスクグラフの確率表示の対象外
  （発生するかしないかの二値であり、確率分布ではないため）

### 条件式で参照可能なパラメータ

| カテゴリ | パラメータ例 |
| --------- | ------------- |
| EVM指標 | SPI, CPI, EV, AC, PV |
| メンバー状態 | avgMorale（平均心）, avgHealth（平均体）, memberCount |
| 特定メンバー | member('名前').心, member('名前').体 |
| 進捗 | taskCompletionRate, phaseProgress('工程名') |
| 経過 | currentTurn |
| カード使用履歴 | cardUsed('カード名'), cardUsedCount('カード名') |
| 論理演算 | &&, \|\|, !, 比較演算子（>=, <=, ==, !=, >, <） |

### データ構造

| フィールド | 説明 |
| ----------- | ------ |
| id | ステージ内で一意の識別子 |
| turn | 判定ターン番号 |
| condition | 発生条件（論理式） |
| event | 発生するイベント名（既存のイベント表から参照） |
| params | イベント固有パラメータ（対象メンバー指定、追加タスク内容など） |

### 具体例（3ヶ月ステージ）

```json
[
  {"id": "ev01", "turn": 15, "condition": "SPI >= 0.95",
   "event": "追加要望", "params": {"tasks": ["画面A追加"]}},
  {"id": "ev02", "turn": 30, "condition": "cardUsed('残業許可') && avgMorale < 40",
   "event": "離脱", "params": {"target": "lowest_morale"}},
  {"id": "ev03", "turn": 45, "condition": "CPI >= 1.1 && taskCompletionRate >= 0.7",
   "event": "追加予算承認", "params": {"amount": 500}},
  {"id": "ev04", "turn": 20, "condition": "!cardUsed('モニタリング')",
   "event": "仕様変更", "params": {"affectedPhase": "設計"}}
]
```

## 固定イベント

ステージ開始時点のガントチャートには、以下の固定イベントが最初から組み込まれている。
発生タイミングそのものは確定しているが、いずれも
「その時点でランダムイベントが高確率で発生するチェックポイント」として機能する。
工程構成は [要件定義](../01-要件定義/index.md) の「工程構成（ウォーターフォール）」を参照。

| 固定イベント | タイミング | 説明 |
| ------------- | ----------- | ------ |
| キックオフ | ステージ開始時 | 高確率でランダムイベントが発生するチェックポイント |
| デイリー | 毎ターン | 日々の進行に伴うチェックポイント。カード「デイリー」を使うと、これに紐づくランダムイベント（手戻り・停滞など）の発生確率をさらに下げられる |
| 週次進捗会議 | 週次（5ターンごと） | 高確率でランダムイベントが発生するチェックポイント |
| 締め | 各工程の終了時 | 高確率でランダムイベントが発生するチェックポイントであり、かつ該当工程のタスクが十分完了していない状態で突入すると「締め失敗停滞」が発生し、後続タスクがすべて停滞する |
| クロージング | ステージ終了時 | 高確率でランダムイベントが発生するチェックポイント |

締め失敗停滞の状態でも、カード「強制締め」を使うことで未完了のまま工程を締めることができるが、
使用後は手戻りの発生確率が大きく上昇する。カードの詳細は [カード](./カード.md) を参照。

## プロジェクトイベント

すべて条件付きイベントとしてステージデータに定義される（ランダム抽選では発生しない）。
個別イベントの内容は `イベント/` 配下の各ファイルを参照
（追加要望・仕様変更・値下げ要求・監査対応・検収不合格・追加予算承認・早期検収）。

## タスクイベント

すべてランダムイベント（毎ターンのリスクグラフ確率に基づく抽選で発生）。
個別イベントの内容は `イベント/` 配下の各ファイルを参照
（手戻り・ブロッカー発生・仕様不明確・環境障害・ひらめき・一発合格・過大報告発覚・
過小報告発覚・報告漏れ）。

## メンバーイベント

離脱・応援要員は条件付きイベント、それ以外はランダムイベント。
個別イベントの内容は `イベント/` 配下の各ファイルを参照
（体調不良・離脱・モチベーション低下・疲労蓄積・休息・地元優勝・応援要員）。

「オンボーディング」はカード「メンバー追加」の使用によって確定で発生する誘発イベントであり、
ランダムには発生しない。
対象となった既存メンバーには「トレーニング停滞」（下記「手戻り・停滞」を参照）が発生する。

## フレーバーテキスト

フレーバーテキストは雰囲気・ネタ要素であり、ゲーム効果には影響しない。
同じ効果でも複数のフレーバーテキストのいずれかが表示される。

## 手戻り・停滞

| 種別 | 発生条件 | 解消方法 |
| ------ | --------- | --------- |
| 手戻り | 完了済タスクに発生し、進捗が下がる | 対象タスクが担当メンバーの通常の進捗ダイスで自然に再完了を目指す。手戻り専用ではない汎用の進捗ブーストカードも使用可 |
| 純粋停滞 | メンバー本人の問題により進捗が停止する | PMがカード「停滞対応」を対象メンバー本人に使うことで再開する |
| ブロッカー停滞 | 対象メンバー以外の責任（ブロッカータスクの担当者側の問題）により進捗が停止する | PMがカード「停滞対応」をブロッカータスクの担当メンバーに使うことで再開する |
| 締め失敗停滞 | 工程の「締め」にタスクが十分完了していない状態で突入し、後続タスクすべてが停止する | 現時点ではカード「強制締め」で未完了のまま締めることでのみ解消できる想定。工程単位で後続タスク全体を止める点、解消手段が個別のタスク停滞と異なる点で、純粋停滞・ブロッカー停滞とは区別する。解消手段は今後「強制締め」以外にも追加予定 |
| トレーニング停滞 | カード「教育」「ペアプログラミング」の使用、または誘発イベント「オンボーディング」の発生によって、対象メンバーが一時的に停滞する | PMの追加対応は不要で、一定期間の経過により自動的に解除される。解除と同時に対象メンバーの経験値が増加する（教育・ペアプログラミングは効果対象のメンバー、オンボーディングは新規メンバーの経験値が増加する）。技のレベルアップ自体は、経験値が閾値に達した時点で起こる（詳細は [メンバー](../02-基本設計/メンバー.md) の「技（レベル）と経験値」を参照） |

手戻りが発生したタスクは、PERT図上の後続タスクの進捗も、対象タスクが再び完了するまで進まなくなる。
締め失敗停滞は個別タスクではなく工程単位で発生するため、
カテゴリとしては進捗ダウンに含め、ガントチャート計算に反映する。
トレーニング停滞は、ネガティブイベントによる停滞ではなく、
PMの育成判断（教育・ペアプログラミング）や制度上の必然（オンボーディング）から生じる、
「一時的に停滞するが経験値が増え、技の成長が早まる」という意図的なトレードオフである点で、
他の停滞と性質が異なる。

## 未決定・要検討事項

- ランダムイベントの発生確率のベース値、およびカード効果による補正の合成方法（加算か倍率か）
- 上表のイベント名・効果は草案であり、内容の追加・削除・バランス調整は今後行う
- 「早期検収」のような、フレーバー止まりで具体的なゲーム上の効果が未確定なイベントの扱い
- 「報告漏れ」の具体的な効果
- 「心」を上昇させる「コミュニケーションイベント（カード）」の対象範囲の確定
- メンバー稼働系・バフ系・デバフ系の各カテゴリについて、
  ガントチャート計算以外の処理（コスト集計・メンバー状態更新・確率補正など）との具体的な対応付け
- 「締め失敗停滞」の解消手段を「強制締め」以外にも追加する（内容は今後検討）
- リスクグラフのカテゴリ間で該当イベント数の偏りが大きい
  （例: 進捗ダウンは5イベント、スコープ変化系は条件付きイベントに移行し0イベント）。
  カテゴリの粒度を見直すか、ランダムイベントの追加で埋めるかは後で是正する
- 条件付きイベントの条件式の具体的な構文仕様（パーサーの実装方針）
- 各ステージの条件付きイベントリストの具体的な内容（ステージデータとして別途設計）
