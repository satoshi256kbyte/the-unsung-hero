# バランスパラメータ（仮値）

実装のための具体的な数値・計算式を定義する。
すべて **仮値** であり、テストプレイ後に調整する。

**設計ゴール**: プロジェクト管理初心者が基本カード（デイリー・レビュー・モニタリング・
サマライズ）のみを使い続けた場合、利益率が5%未満（ギリギリクリアまたは失敗）になること。

## 3. 進捗ダイスの計算式

1ターンに1タスクを担当するメンバーが進める進捗量（%単位）。

```
進捗上昇量 = base × skill_factor(技) × health_factor(体)

base    = 一様乱数(3.0, 7.0)   ← 1日の計画上昇量を約5%とした場合の基準幅
          ※ タスク総量を100%として、22日÷3工程のタスク数で割った値に合わせて調整
```

### skill_factor（技による高止まり補正）

技が高いほど下振れが抑えられ、計画値付近で安定する。

| 技レベル | skill_factor | 意味 |
|---------|-------------|------|
| 0〜4 | 乱数(0.6, 1.2) | 大きくばらつく |
| 5〜9 | 乱数(0.75, 1.15) | 中程度のばらつき |
| 10〜14 | 乱数(0.85, 1.10) | 計画値付近で安定 |
| 15〜24 | 乱数(0.90, 1.08) | ほぼ計画通り |
| 25以上 | 乱数(0.95, 1.05) | ほぼ確実に計画値 |

### health_factor（体による下振れ補正）

体が低いほど下振れしやすくなる。上振れには影響しない。

| 体の値 | health_factor |
|--------|-------------|
| 70以上 | 1.0（補正なし） |
| 50〜69 | 乱数(0.85, 1.0) |
| 30〜49 | 乱数(0.70, 1.0) |
| 0〜29 | 乱数(0.50, 1.0) |

## 4. 経験値とレベルアップ

### タスク完了時の経験値

```
獲得経験値 = base_exp × level_factor(技)

base_exp    = 10（タスク1本完了時）
level_factor = max(0.3, 1.0 − 技 × 0.04)

技 0  → level_factor = 1.00 → 経験値10
技 8  → level_factor = 0.68 → 経験値7
技 10 → level_factor = 0.60 → 経験値6
技 20 → level_factor = 0.20（0.3に切り上げ）→ 経験値3
```

### レベルアップ必要経験値テーブル

次の技レベルになるために必要な累積経験値（現レベルからの差分）。

| 現技レベル | 必要経験値 |
|-----------|----------|
| 0〜4 | 30 |
| 5〜9 | 50 |
| 10〜14 | 80 |
| 15〜24 | 120 |
| 25〜49 | 200 |
| 50〜 | 400 |

1ヶ月ステージ（22日・タスク数約8本）での最大取得経験値:
技8のメンバーが全タスクをこなした場合 ≒ 8×7 = 56。
技5〜9ゾーンの必要経験値50を超えるため、運良く手戻りなく進めば1レベルアップ可能。

### カードによる経験値ブースト

| 教育 | +30 | される側 |

## 7. ランダムイベント発生確率

### タスクイベント（有効タスク1本あたり・1ターン）

| イベント | 基本確率 | カード使用時 |
|---------|---------|-----------|
| 手戻り | 8% | デイリー+レビュー使用で 5% |
| 仕様不明確（純粋停滞） | 5% | デイリー使用で 3% |
| ブロッカー発生 | 4% | デイリー使用で 3% |
| 環境障害 | 3% | 低減不可 |
| 過大報告発覚 | 4% | モニタリング使用で 2% |
| 過小報告発覚 | 3% | モニタリング使用で 1% |
| 報告漏れ | 3% | モニタリング使用で 1% |
| ひらめき | 3% | 変化なし |
| 一発合格 | 2% | 変化なし |

### メンバーイベント（メンバー1人あたり・1ターン）

| イベント | 基本確率 | 修正条件 |
|---------|---------|---------|
| 体調不良 | 5% | 体<50 で ×2（10%） |
| モチベーション低下 | 6% | 心<60 で ×2（12%） |
| 疲労蓄積 | 4% | 緊張感>130 で ×1.5 |
| 休息 | 3% | 変化なし |
| 地元優勝 | 2% | 変化なし |

### 確率補正の合成方式

複数カードの効果が重なる場合は **最も低い確率を採用**（スタック不可）。
パラメータによる修正（×2など）はカード補正後の値に乗算する。

```
最終確率 = min(各カード効果適用後の確率値) × パラメータ補正倍率
```

### 手戻りの巻き戻し量

```
巻き戻し率 = 40% − (技 × 1%)

技 10 → 30% 巻き戻し（進捗70%地点に後退）
技  8 → 32% 巻き戻し
技  4 → 36% 巻き戻し
```

### 停滞の持続ターン数

| 種別 | 分布 | 心への影響 |
|------|------|---------|
| 純粋停滞 | 1ターン:60% / 2ターン:40% | −12 |
| ブロッカー停滞 | 1ターン:60% / 2ターン:40% | −12 |
| 締め失敗停滞 | 強制締めカード使用まで継続 | −20 |

## 10. バランス検証シミュレーション

### シナリオA: 初心者（デイリー系4枚のみ使用）

```
基本前提:
  - デイリー・レビュー・モニタリング・サマライズを毎ターン使用（4コスト）
  - それ以外のカードは使わない
  - 心・体管理なし

想定ネガティブイベント発生数（22ターン × 2タスク並行）:
  - 手戻り: 22×2×5% = 2.2件
  - 停滞: 22×2×(3+3)% = 2.6件
  - 体調不良: 22×2×5% = 2.2件（計1日分の稼働損）
  - 週次でのランダムイベント: 0.65件/回 × 4回 = 2.6件
  - 合計: 約9〜10件

コスト超過推計:
  - 手戻り1件 ≒ 巻き戻し30%分の追加作業 = バッファを約2.4%消費
  - 停滞1件（平均1.4ターン）= バッファを約3%消費
  - 合計: 2.2×2.4% + 2.6×3% + キックオフ等イベント ≒ バッファを約20〜22%消費

推定利益率: 25% − 20〜22% = 3〜5%（ギリギリラインまたはわずかに失敗）
```

### シナリオB: 熟練者（状況に応じてカードを切り替え）

```
追加対応:
  - 停滞発生時に停滞対応カード（1コスト）を使用
  - 心<70で個別面談（2コスト）を使用
  - 締め前に進捗が遅れていたら進捗ブースト（3コスト）を使用
  - poc-ev03（追加予算承認）の条件を満たす

推定追加コスト消費: バッファの約5〜8%
推定利益率: 25% − 10〜12% + 8%（追加予算） = 13〜23%
```

### シナリオC: 最悪手（基本カードを止めハイリスクカードを濫用）

```
想定:
  - デイリー系をすべて外し、残業許可・休出を多用

推定:
  - ネガティブイベント確率がカード低減なしで約24%/タスク/ターン
  - 締め失敗停滞が確定的に発生し、コスト超過
  - バッファ消費100%超 → 即ゲームオーバー
```

## 11. 調整優先度

テストプレイ後の調整は以下の順で行う。

1. **手戻りの巻き戻し率**（利益への直撃度が最大）
2. **チェックポイント確率**（固定イベント9回の累積影響大）
3. **心・体の自然低下量**（放置プレイの悪化速度に直結）
4. **停滞の持続ターン数分布**（2人体制での影響が大きい）
5. **週末回復量**（低下量と対になる値）
