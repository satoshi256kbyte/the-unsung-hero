# バランスパラメータ

実装のための計算式・パラメータの意味を定義する。
**具体的な数値はチューニングのたびに変わるため、ここには書かない**
（[ADR-022](../superpowers/specs/2026-08-14-json-data-externalization-design.md)）。
現在値は各項目に記載したJSONファイルを参照すること。

**設計ゴール**: プロジェクト管理初心者が基本カード（デイリー・レビュー・モニタリング・
サマライズ）のみを使い続けた場合、利益率が`GLOBAL_RULES.TARGET_PROFIT_RATE`未満
（ギリギリクリアまたは失敗）になること。

## 3. 進捗ダイスの計算式

1ターンに1タスクを担当するメンバーが進める進捗量（%単位）。

```
進捗上昇量 = base × skill_factor(技) × health_factor(体)

base = 一様乱数(PROGRESS_DICE.BASE_MIN, PROGRESS_DICE.BASE_MAX)
       ← public/data/balance/constants.json の PROGRESS_DICE を参照
       ※ タスク総量を100%として、稼働日数÷工程数のタスク数で割った値に合わせて調整
```

### skill_factor（技による高止まり補正）

技が高いほど下振れが抑えられ、計画値付近で安定する。技レベル帯ごとの
`[min, max]`テーブルは`public/data/balance/constants.json`の
`SKILL_FACTOR_TABLE`を参照（技が高いほどレンジが1.0付近に収束する設計）。

### health_factor（体による下振れ補正）

体が低いほど下振れしやすくなる。上振れには影響しない。体の値帯ごとの
`[min, max]`テーブルは`public/data/balance/constants.json`の
`HEALTH_FACTOR_TABLE`を参照（体が高いほどレンジが1.0付近に収束する設計）。

## 4. 経験値とレベルアップ

### タスク完了時の経験値

```
獲得経験値 = base_exp × level_factor(技)

base_exp     = public/data/balance/constants.json の EXP.BASE_EXP
level_factor = max(EXP.LEVEL_FACTOR_MIN, 1.0 − 技 × EXP.LEVEL_FACTOR_COEFF)
```

技が高いほど`level_factor`が下がり、1タスクあたりの獲得経験値が減る
（技が低いメンバーほど経験値を稼ぎやすい設計）。

### レベルアップ必要経験値テーブル

次の技レベルになるために必要な累積経験値（現レベルからの差分）。技レベル帯ごとの
必要経験値テーブルは`public/data/balance/constants.json`の`LEVEL_UP_EXP`を参照。

### カードによる経験値ブースト

教育・ペアプログラミングカード使用時の付与経験値は、
`public/data/balance/constants.json`の`EXP.EDUCATION_GRANT`
`EXP.PAIR_PROG_GRANT`を参照（カード自体のコストは
`public/data/cards/教育.json` `public/data/cards/ペアプログラミング.json`、
付与経験値量はバランス係数側で管理する）。

### トレーニング停滞の持続期間

教育・ペアプログラミング・オンボーディングそれぞれの停滞ターン数は
`public/data/balance/constants.json`の`STALL.EDUCATION_STALL_TEACHER`
`STALL.EDUCATION_STALL_LEARNER` `STALL.PAIR_PROG_STALL` `STALL.ONBOARDING_STALL`
を参照。

## 5. 心・体・透明性・緊張感の変動

### 自然変動（毎ターン）

| パラメータ | 参照先 | 備考 |
| ----------- | ------- | ------ |
| 心 | `PARAM_DELTA.MORALE_NATURAL_MIN`〜`MAX`（一様乱数、整数） | 週末2日で自然回復あり（下記） |
| 体 | `PARAM_DELTA.HEALTH_NATURAL_MIN`〜`MAX`（一様乱数、整数） | 毎ターン自然低下のみ（上昇は回復手段のみ） |
| 透明性 | ターン経過による変動なし | カード・イベントのみで変動 |
| 緊張感 | `PARAM_DELTA.TENSION_NATURAL_DELTA`/ターン（納期が遠い間） | 締め失敗・手戻り多発時に上昇 |

数値はいずれも`public/data/balance/constants.json`の`PARAM_DELTA`を参照。

### 週末回復（5稼働日ごとに自動適用）

心・体の回復量は`PARAM_DELTA.WEEKEND_MORALE_RECOVERY` `PARAM_DELTA.WEEKEND_HEALTH_RECOVERY`
を参照。

### ネガティブイベント発生の閾値

心・体・透明性・緊張感それぞれの「低すぎる／高すぎる」閾値は
`public/data/balance/constants.json`の`THRESHOLDS`を参照。心・緊張感は
低いほどネガティブイベント確率が上昇し、高すぎても別のイベントを誘発する。
体は低いほど進捗下振れ・体調不良確率が上昇する（上限なし、100が最大）。
透明性は低いほど報告漏れ・過大報告確率が、高すぎると情報過多イベント確率が上昇する。

### カードによる変動量

雑談・個別面談・表彰・計画休それぞれの変動量は`public/data/balance/constants.json`の
`PARAM_DELTA.CHAT_MORALE_MITIGATION` `PARAM_DELTA.ONE_ON_ONE_MORALE`
`PARAM_DELTA.COMMENDATION_MORALE` `PARAM_DELTA.PLANNED_LEAVE_MORALE`/
`PLANNED_LEAVE_HEALTH`を参照。カード自体のコストは各`public/data/cards/*.json`。

### イベントによる変動量

体調不良・手戻り・停滞・締め失敗停滞・ひらめき・休息・地元優勝それぞれの
心・体への影響量は`public/data/balance/constants.json`の`PARAM_DELTA`内の
`EVENT_*`キー群を参照。

## 6. カードのコスト

「低・中・高・特大」という段階の大まかな目安は残すが、各カードの具体的な
コスト数値は`public/data/cards/<カード名>.json`の`cost`を参照
（例:「低」= 最小コスト帯、「特大」= 最大コスト帯）。個別カードの
コスト値一覧は`docs/03-詳細設計/カード/`配下の各ファイルを参照。

1日の上限コストは`public/data/balance/constants.json`の
`GLOBAL_RULES.DAILY_COST_CAP`を参照。デイリー・レビュー・モニタリング・
サマライズを全部使った場合の消費量は、それぞれの`cost`の合計として計算できる。

### 残業許可の効果

1枚使用で翌日から一定期間、全員の1日上限を`GLOBAL_RULES.DAILY_COST_CAP`から
`GLOBAL_RULES.OVERTIME_COST_CAP`に引き上げる。持続期間・拡張分の追加消費量は
実装（`src/game/cards/overtime-permission.ts`）を参照。

### 強制締め後のペナルティ

手戻り発生確率が一定ターン数だけ上昇する（倍率・持続ターン数は
実装（`src/game/cards/forced-closing.ts`）を参照）。

## 7. ランダムイベント発生確率

各イベントの基本確率・カード使用時の派生確率は`public/data/events/<イベント名>.json`
（`baseProb`および派生確率キー）を参照。個別イベントの一覧は
`docs/03-詳細設計/イベント/`配下の各ファイルを参照。

体調不良・モチベーション低下・疲労蓄積のように、パラメータ（体・心・緊張感）に
応じて確率が倍率補正される修正条件がある場合、倍率自体は実装
（`src/game/events/<イベント名>.ts`）を参照。

### 確率補正の合成方式

複数カードの効果が重なる場合は **最も低い確率を採用**（スタック不可）。
パラメータによる修正（×2など）はカード補正後の値に乗算する。

```
最終確率 = min(各カード効果適用後の確率値) × パラメータ補正倍率
```

### 手戻りの巻き戻し量

```
巻き戻し率 = REWORK.ROLLBACK_BASE − (技 × REWORK.ROLLBACK_COEFF)
```

技が高いほど巻き戻し率が下がる（進捗の後退が小さくなる）。係数は
`public/data/balance/constants.json`の`REWORK`を参照。

### 停滞の持続ターン数

純粋停滞・ブロッカー停滞の持続ターン数分布は`public/data/balance/constants.json`の
`STALL.ONE_TURN_PROB` `STALL.TWO_TURN_PROB`を参照。締め失敗停滞は強制締めカード
使用まで継続する。それぞれの心への影響量は`PARAM_DELTA.EVENT_STALL_MORALE`
`PARAM_DELTA.EVENT_STALL_DEADLINE_MORALE`を参照。

---

## 8. 固定イベント（チェックポイント）確率

キックオフ・週次進捗会議・締め・クロージングそれぞれの発生確率は
`public/data/balance/constants.json`の`CHECKPOINT_PROB`を参照。抽選対象
（キックオフ＝仕様不明確・ブロッカー発生、週次進捗会議＝全タスク・メンバーイベント、
締め＝手戻り・仕様不明確、クロージング＝全イベント）は変更なし。

締め失敗しきい値（完了率がこれを下回ると締め失敗停滞が確定発生する）は
`THRESHOLDS.MILESTONE_FAIL_RATE`を参照。

## 10. バランス検証シミュレーション

### シナリオA: 初心者（デイリー系4枚のみ使用）

```
基本前提:
  - デイリー・レビュー・モニタリング・サマライズを毎ターン使用（4コスト）
  - それ以外のカードは使わない
  - 心・体管理なし

想定ネガティブイベント発生数（22ターン × 2タスク並行）:
  - 手戻り: 22×2×5% = 2.2件
  - 停滞: 22×2×(3+3)% = 2.6件
  - 体調不良: 22×2×5% = 2.2件（計1日分の稼働損）
  - 週次でのランダムイベント: 0.65件/回 × 4回 = 2.6件
  - 合計: 約9〜10件

コスト超過推計:
  - 手戻り1件 ≒ 巻き戻し30%分の追加作業 = バッファを約2.4%消費
  - 停滞1件（平均1.4ターン）= バッファを約3%消費
  - 合計: 2.2×2.4% + 2.6×3% + キックオフ等イベント ≒ バッファを約20〜22%消費

推定利益率: 25% − 20〜22% = 3〜5%（ギリギリラインまたはわずかに失敗）
```

### シナリオB: 熟練者（状況に応じてカードを切り替え）

```
追加対応:
  - 停滞発生時に停滞対応カード（1コスト）を使用
  - 心<70で個別面談（2コスト）を使用
  - 締め前に進捗が遅れていたら進捗ブースト（3コスト）を使用
  - poc-ev03（追加予算承認）の条件を満たす

推定追加コスト消費: バッファの約5〜8%
推定利益率: 25% − 10〜12% + 8%（追加予算） = 13〜23%
```

### シナリオC: 最悪手（基本カードを止めハイリスクカードを濫用）

```
想定:
  - デイリー系をすべて外し、残業許可・休出を多用

推定:
  - ネガティブイベント確率がカード低減なしで約24%/タスク/ターン
  - 締め失敗停滞が確定的に発生し、コスト超過
  - バッファ消費100%超 → 即ゲームオーバー
```

## 11. 調整優先度

テストプレイ後の調整は以下の順で行う。

1. **手戻りの巻き戻し率**（利益への直撃度が最大）
2. **チェックポイント確率**（固定イベント9回の累積影響大）
3. **心・体の自然低下量**（放置プレイの悪化速度に直結）
4. **停滞の持続ターン数分布**（2人体制での影響が大きい）
5. **週末回復量**（低下量と対になる値）
