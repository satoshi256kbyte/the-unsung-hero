# 要件定義

## 概要

PMとなってプロジェクトを完遂しつつ、一定以上の利益を得ることを目指す、
プロジェクトマネジメント×SRPGのシミュレーションゲーム。
ウォーターフォール型のプロジェクトを、ガントチャート・PERT図・EVMを見ながら1日1ターンで進行させる。
メンバーの「技」はSRPGにおけるレベルに相当し、タスクをこなして得た経験値によって成長していく
（詳細は [メンバー](../02-基本設計/メンバー.md) の「技（レベル）と経験値」を参照）。

## ステージ構成

- 期間は1ヶ月・3ヶ月・6ヶ月・12ヶ月のいずれか
- ステージ間の引き継ぎ要素はなし（ステージセレクト → プレイ → クリア／失敗で完結）
- 受注後のプロジェクト開始からステージスタート
- 納期到達時にガントチャートが完了していれば利益計算へ進む
- 利益計算の結果、目標利益を超えていればクリア

1ヶ月ステージは、PoC（概念実証）案件を想定した、気楽に遊べる短期ステージという位置づけ。
工程構成・メンバー人数がほかのステージと異なる
（詳細は [ターン制とカード](../02-基本設計/ターン制とカード.md) の「工程構成」、
[メンバー](../02-基本設計/メンバー.md) の「メンバー人数」を参照）。
固定イベントの構成（キックオフ・デイリー・週次進捗会議・締め・クロージング）を含め、
それ以外のルールは共通。

## ステージデータ

各ステージはレベルデータとして事前に設計される。以下の要素で構成される。

- ガントチャート（タスク構成・依存関係・各タスクの期間）
- 仕様追加・リスケ後のガントチャートバリエーション（後述）
- 条件付きイベントリスト（発生ターン・条件式・イベント内容）
- 初期メンバー構成
- 予算・納期

ガントチャートや条件付きイベントはランダム生成ではなく、
ステージごとに意図的な難易度カーブやドラマを設計するための固定データである。

### ガントチャート変更の事前定義

仕様追加（追加要望イベント）やリスケ（カード使用）によるガントチャートの変更は、
実行時にアルゴリズムで計算するのではなく、変更後の状態を事前作成データとして持つ。

- 追加要望イベントが発生した場合の「タスク追加後ガントチャート」
- リスケカード使用時の「再スケジュール後ガントチャート」

これらはステージデータの一部として事前に設計し、
イベント発生時・カード使用時に対応するデータに差し替える形で反映する。
条件付きイベントの詳細は [イベント](../03-詳細設計/イベント.md) の「条件付きイベント」を参照。

## 工程構成（ウォーターフォール）

一般的なウォーターフォール開発に従い、要件定義から受入テストまでを想定する
（草案、工程の粒度は後で見直す可能性がある）。

1. 要件定義
2. 基本設計
3. 詳細設計
4. 実装
5. 単体テスト
6. 結合テスト
7. 総合テスト
8. 受入テスト

各工程の終了タイミングは固定イベント「締め」に対応する。
詳細は [イベント](../03-詳細設計/イベント.md) の「固定イベント」を参照。

1ヶ月ステージ（PoC想定）は以下の工程のみとする

1. 設計
2. 実装
3. テスト

## 勝利条件

- 納期到達時にガントチャートが完了していること
- 利益計算の結果、目標利益を超えていること

## 失敗条件

- 総消費コストが予算の100%を超えた場合、即ゲームオーバー
- 納期到達時にガントチャートが未完了で、カード「交渉」による納期延期を使用しなかった、
  または失敗した場合、即ゲームオーバー

  標準4人ステージの10・8・6・4のうちどの2つを使うか、それとも専用の構成にするか

- 技の最大値が99に定まったことに伴う、進捗ダイスの計算
  （技による「高止まり」の度合い）の具体的な閾値の再調整
- 「目標利益を超えなかった場合」の扱い
  （失敗と同じ扱いにするか、別のランクにするか）は未決定
