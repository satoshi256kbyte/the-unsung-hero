# Feature Specification: メンバーパラメータ変動エンジン

**Feature Branch**: `004-member-params-engine`

**Created**: 2026-08-13

**Status**: Draft

## User Scenarios & Testing

### User Story 1 - 毎ターンの心・体が自然変動する (Priority: P1)

ゲームエンジンが各ターン終了時にメンバーの心・体パラメータを自然変動させられる。
心は -3〜+1 の整数乱数で変動し、体は -3〜-1 の整数で自然低下する。
どちらも定義された範囲（心 0〜150、体 0〜100）を超えることなくクランプされる。

**Why this priority**: 毎ターン必ず発生する基本処理。
これがなければメンバー管理の全要素（カード効果・イベント発生確率）が成立しない。

**Independent Test**: メンバーに applyTurnDecay を適用したとき、
心が 0〜150 の範囲内、体が 0〜100 の範囲内に収まることを確認できる。

**Acceptance Scenarios**:

1. **Given** 心100・体100 のメンバー、**When** applyTurnDecay を適用、
   **Then** 心は 97〜101 の間（クランプ後 0〜150）、体は 97〜99 の間（クランプ後 0〜100）
2. **Given** 心0・体0 のメンバー（最小値）、**When** applyTurnDecay を適用、
   **Then** 心・体ともに 0 以下にならない（0 にクランプ）
3. **Given** 心150・体100 のメンバー（最大値）、**When** applyTurnDecay を適用、
   **Then** 心・体ともに最大値を超えない

---

### User Story 2 - 週末に心・体が自動回復する (Priority: P2)

5稼働日（ターン）ごとに週末回復が自動適用される。
心は +8、体は +12 回復するが、それぞれの上限（150・100）を超えることはない。

**Why this priority**: 週末回復は長期プレイでのバランス維持に不可欠。
回復なしでは22ターンで体がゼロになり進捗が大幅低下する。

**Independent Test**: applyWeekendRecovery を呼び出したとき、
心が最大8・体が最大12増加し、各上限を超えないことを確認できる。

**Acceptance Scenarios**:

1. **Given** 心90・体80 のメンバー、**When** applyWeekendRecovery を適用、
   **Then** 心は 98、体は 92 になる
2. **Given** 心145・体95 のメンバー（上限近く）、**When** applyWeekendRecovery を適用、
   **Then** 心は 150（上限にクランプ）、体は 100（上限にクランプ）

---

### User Story 3 - タスク完了時に経験値が付与されレベルアップする (Priority: P3)

タスク完了時に経験値が付与され、LEVEL_UP_EXP テーブルの閾値に達したら技が 1 上がる。
技が上がると経験値がリセットされ、技の上限は 99。

**Why this priority**: 成長システムの基盤。
Spec-05（ターン処理エンジン）がタスク完了時にこの関数を呼び出す。

**Independent Test**: applyExperience を呼び出したとき、
経験値が正しく加算され、閾値到達時に技 +1・経験値リセットが行われることを確認できる。

**Acceptance Scenarios**:

1. **Given** 技8・経験値40 のメンバー、閾値50、**When** 経験値 +15 を付与、
   **Then** 技 9・経験値 5（50を超えた分がリセット後に残る）
2. **Given** 技99（最大）・経験値 0 のメンバー、**When** 経験値 +100 を付与、
   **Then** 技は 99 のまま（上限超えない）
3. **Given** 技10・経験値 0 のメンバー（閾値80）、**When** 経験値 +50 を付与、
   **Then** 技は変わらず 10・経験値は 50

---

### Edge Cases

- 心・体がすでに 0 のとき、さらに自然低下しても 0 のまま（下限クランプ）
- 心・体がすでに上限のとき、週末回復しても上限のまま（上限クランプ）
- 技が 99 のとき、どれだけ経験値を積んでも 99 のまま
- 経験値付与量が 0 以下の場合は変化なし（ガード）

## Requirements

### Functional Requirements

- **FR-001**: システムは、毎ターン心を整数乱数(-3〜+1)で変動させ、0〜150 の範囲にクランプしなければならない
- **FR-002**: システムは、毎ターン体を整数乱数(-3〜-1)で変動させ、0〜100 の範囲にクランプしなければならない
- **FR-003**: システムは、週末回復として心を +8・体を +12 加算し、それぞれの上限にクランプしなければならない
- **FR-004**: システムは、経験値付与時に `base_exp × max(0.3, 1.0 - skill × 0.04)` の計算式で獲得量を決定しなければならない
- **FR-005**: システムは、累積経験値が LEVEL_UP_EXP テーブルの閾値に達したとき、技を +1 し経験値を閾値超過分にリセットしなければならない
- **FR-006**: システムは、技の上限 99 を超えてレベルアップさせてはならない
- **FR-007**: システムは、Phaser および DOM API に一切依存してはならない
- **FR-008**: システムは、引数の Member オブジェクトを変更してはならない（イミュータブル操作）

### Key Entities

- **Member**: 技（0〜99）・経験値（0以上）・心（0〜150）・体（0〜100）を持つゲームキャラクター
- **LEVEL_UP_EXP**: 技レベル帯ごとの必要経験値テーブル（技0〜4: 30、5〜9: 50、10〜14: 80 …）

## Success Criteria

### Measurable Outcomes

- **SC-001**: 全関数の型チェックがエラーゼロで通る
- **SC-002**: 心・体の境界値テスト（0/1/99/100/149/150）が全件 PASS する
- **SC-003**: 技レベルアップの境界値テスト（各帯の閾値前後）が全件 PASS する
- **SC-004**: fast-check プロパティテストで任意の心(0〜150)・体(0〜100)・技(0〜99)・経験値(0〜500) を入力しても
  パニックせず全パラメータが範囲内に収まることを確認できる
- **SC-005**: `grep -r "phaser\|document\|window" src/game/member.ts` が 0 件

## Assumptions

- Member 型は Spec-01 の `src/game/types.ts` で定義済みであることを前提とする
- PARAM_DELTA・MEMBER_PARAMS・EXP・LEVEL_UP_EXP は Spec-01 の `src/game/constants.ts` に定義済みであることを前提とする
- applyExperience に渡す expGain は呼び出し側（Spec-05）が計算して渡す。
  この関数内では加算のみ行い、レベルアップ判定を行う
- 週末回復の「5稼働日ごと」のターン判定は Spec-05（ターン処理エンジン）側が担う。
  applyWeekendRecovery は「回復を適用する」純粋関数のみを提供する
- 複数回のレベルアップ（1度の経験値付与で技が2以上上がるケース）は考慮しない（1付与=最大1レベルアップ）
