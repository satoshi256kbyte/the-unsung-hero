# Feature Specification: ゲームクリア/失敗のリザルト画面

**Feature Branch**: `021-result-screen`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "ゲームクリア/失敗のリザルト画面（利益率の最終表示、成否判定の提示）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - プレイヤーがゲーム終了時に成否と最終利益率を確認できる (Priority: P1)

プレイヤー（PM役）は、プロジェクトが終了（全タスク完了、または納期到達）したとき、
専用のリザルト画面で「クリア／失敗」の判定と、最終的な利益・利益率を確認できる。
これにより、そのプレイの結果が一目で分かり、達成感または再挑戦の動機を得られる。

**Why this priority**: 現状はゲーム終了条件（全タスク完了・納期超過）が内部的に判定されるものの、
プレイヤーに結果を提示する画面が無く、ターンを確定してもダッシュボードが再描画されるだけで
ゲームが終わったことも成否も分からない。リザルト提示はゲームの区切りを成立させる中核であり、
これが無いと「プレイの目的（目標利益率の達成）を達成できたか」が伝わらない。

**Independent Test**: ゲームを終了状態（全タスク完了または納期到達）まで進めると、
リザルト画面が表示され、成否判定（クリア／失敗）と最終利益率が確認できることを検証できる。

**Acceptance Scenarios**:

1. **Given** 全タスクが完了してゲームが終了した, **When** ターンを確定する,
   **Then** リザルト画面が表示され、成否判定と最終利益・最終利益率が示される
2. **Given** 納期に到達してゲームが終了した, **When** ターンを確定する,
   **Then** リザルト画面が表示され、成否判定と最終利益・最終利益率が示される
3. **Given** ゲームが終了していない（タスク未完了かつ納期前）, **When** ターンを確定する,
   **Then** リザルト画面は表示されず、従来どおりダッシュボードに戻る

---

### User Story 2 - プレイヤーが成否の理由と結果の内訳を理解できる (Priority: P2)

プレイヤーは、リザルト画面で「なぜクリア／失敗したのか」（目標利益率を達成した／しなかった、
納期内に完遂した／納期超過した）と、判断の根拠となる主要な数値（目標利益率、達成利益率、
予算、総消費コスト、経過ターン、タスク完了状況）を確認できる。

**Why this priority**: 単に成否だけでなく、その理由と内訳が分かることで、次のプレイでの
改善につながる。US1（成否と利益率の提示）が動くことが前提だが、学習・再挑戦の質を高める。

**Independent Test**: 異なる終了状況（納期内クリア／納期超過失敗／目標利益率未達）で
それぞれリザルト画面を表示し、成否理由と主要数値が状況に応じて正しく示されることを検証できる。

**Acceptance Scenarios**:

1. **Given** 目標利益率を達成してクリアした, **When** リザルト画面を見る,
   **Then** クリア理由（目標利益率達成）と、目標利益率・達成利益率・予算・総消費コスト・
   経過ターンが示される
2. **Given** 納期超過で失敗した, **When** リザルト画面を見る,
   **Then** 失敗理由（納期超過）と主要数値が示される
3. **Given** 全タスク完了したが目標利益率に届かなかった, **When** リザルト画面を見る,
   **Then** 失敗（またはクリア）判定が成否ルールに従って示され、達成利益率が目標を下回ることが分かる

---

### User Story 3 - プレイヤーがリザルト画面から次の行動を選べる (Priority: P3)

プレイヤーは、リザルト画面から「タイトルへ戻る」などの次の行動を選び、
ゲームの区切りをつけて再スタートの起点に戻れる。

**Why this priority**: リザルトを見た後の導線が無いと画面が行き止まりになる。
US1・US2に比べ影響は限定的だが、ゲームループを閉じるために必要。

**Independent Test**: リザルト画面で「タイトルへ戻る」を選ぶと、タイトル画面へ遷移し、
そこから再びゲームを開始できることを検証できる。

**Acceptance Scenarios**:

1. **Given** リザルト画面が表示されている, **When** 「タイトルへ戻る」を選ぶ,
   **Then** タイトル画面へ遷移する
2. **Given** タイトルへ戻った, **When** 再度ゲームを開始する,
   **Then** 初期状態の新しいプレイを開始できる

---

### Edge Cases

- 予算が 0 の場合、利益率の計算（利益 ÷ 予算）がゼロ除算にならず、破綻しない値
  （例: 0% 扱い）で表示されること
- 総消費コストが予算を超えた場合（利益が負）、利益率が負の値として正しく表示され、
  失敗として判定されること
- 全タスク完了と納期到達が同一ターンで同時に成立した場合、成否判定と表示する終了理由が
  一意に定まること（優先順位を定義する）
- リザルト画面が表示された後にターン確定操作を再度行っても、ゲームが二重に進行したり
  リザルトが多重表示されたりしないこと

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ゲームが終了した（全タスク完了または納期到達）ターンの確定後に、
  リザルト画面を表示しなければならない
- **FR-002**: システムは、リザルト画面で成否判定（クリア／失敗）を明示しなければならない
- **FR-003**: システムは、成否判定を次のルールで決定しなければならない。最終利益率が目標利益率
  以上、かつ納期内に全タスクを完了した場合をクリアとし、それ以外（目標利益率未達、または
  納期超過による終了）を失敗とする
- **FR-004**: システムは、リザルト画面で最終利益額と最終利益率を表示しなければならない。
  利益は「予算 − 総消費コスト」、利益率は「利益 ÷ 予算」で算出する
- **FR-005**: システムは、リザルト画面で成否の理由（目標利益率の達成可否、納期内完遂か納期超過か）
  を提示しなければならない
- **FR-006**: システムは、リザルト画面で判断根拠となる主要数値（目標利益率、達成利益率、予算、
  総消費コスト、経過ターン、タスク完了状況）を表示しなければならない
- **FR-007**: システムは、ゲームが終了していない場合（タスク未完了かつ納期前）はリザルト画面を
  表示せず、従来どおりの進行画面（ダッシュボード）を維持しなければならない
- **FR-008**: システムは、リザルト画面から「タイトルへ戻る」導線を提供し、選択時にタイトル画面へ
  遷移しなければならない
- **FR-009**: システムは、予算が 0 の場合でも利益率計算がゼロ除算で破綻せず、定義された値
  （0%）を表示しなければならない
- **FR-010**: システムは、全タスク完了と納期到達が同時に成立した場合の終了理由と成否判定を
  一意に定めなければならない（全タスク完了を優先し、納期内完遂として扱う）
- **FR-011**: リザルト画面の表示は、既存のターン処理・ゲーム終了判定（内部の成否条件）を
  壊してはならない。結果の提示方法を追加するのみとする

### Key Entities *(include if feature involves data)*

- **リザルト**: 1回のプレイの終了時に確定する結果。成否判定（クリア／失敗）、終了理由
  （全タスク完了／納期超過）、最終利益、最終利益率、目標利益率、予算、総消費コスト、
  経過ターン、タスク完了状況を持つ
- **成否判定ルール**: 最終利益率と目標利益率の比較、および納期内完遂か否かからクリア／失敗を
  決定する規則

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ゲームが終了した全てのプレイで、ターン確定後にリザルト画面が表示される
  （終了時に結果が提示されないケースが 0 件になる）
- **SC-002**: リザルト画面に表示される最終利益率が、予算・総消費コストから算出される値と
  一致する（表示値と計算値の差異が 0 件）
- **SC-003**: 成否判定が成否ルール（目標利益率以上かつ納期内完遂でクリア、それ以外は失敗）と
  100% 一致する
- **SC-004**: プレイヤーはリザルト画面から操作を止められることなくタイトル画面へ戻り、
  新しいプレイを開始できる（行き止まりが発生しない）
- **SC-005**: リザルト画面導入後も、既存のターン確定・進行・ゲーム終了判定が従来どおり動作する
  （回帰なし）

## Assumptions

- 成否判定は「最終利益率が目標利益率（バランス定義値、現行 5%）以上、かつ納期内に全タスク完了」
  をクリアとする。目標利益率の具体値はバランス調整の対象であり、既存のバランス定義を参照する。
  最終的な判定ルールの細部（境界値の扱い等）は plan 以降で確定する
- 利益・利益率の算出式は既存のダッシュボード表示（利益＝予算−総消費コスト、利益率＝利益÷予算）
  を踏襲する
- 対象ステージは現行唯一の poc-01。将来ステージが追加されても同じリザルト提示ルールを踏襲する
- リザルト画面の具体的なレイアウト・演出・文言は plan 以降で確定する。本 spec は提示すべき
  情報と導線を定義する
- 「タイトルへ戻る」以外の導線（同じステージを再挑戦する等）は本フィーチャーの必須要件では
  なく、必要なら別途検討する

## Dependencies

- 既存のゲーム終了判定（ターン処理が返す終了フラグと終了理由「全タスク完了」「納期超過」）に
  依存する。本フィーチャーはその結果をプレイヤー向けに提示する
- 既存の画面遷移（タイトル → ステージ選択 → メインゲーム）に依存し、メインゲーム終了時の
  遷移先としてリザルトを追加する
- 既存の利益・利益率・目標利益率の定義（ダッシュボード表示、バランス定義値）に依存する

## Out of Scope

- スコア/ランキング、実績・トロフィーなどのメタ進行要素
- リプレイ保存やプレイ履歴の永続化
- リザルト画面での詳細なターンごとのログ・グラフ表示（主要数値のサマリのみを対象とする）
- 複数ステージのクリア状況の集計（対象は単一プレイの結果提示）
