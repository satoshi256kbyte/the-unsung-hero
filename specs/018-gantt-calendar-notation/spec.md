# Feature Specification: docsガントチャート表記見直し（カレンダー列形式）

**Feature Branch**: `018-gantt-calendar-notation`

**Created**: 2026-08-16

**Status**: Draft

**Input**: User description: "Spec-17: docsのステージMarkdownにおけるガントチャート表記見直し（カレンダー列形式）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ステージ設計者がガントチャートを暦日ベースで一望できる (Priority: P1)

ステージの数値・スケジュールを調整する担当者（人間、AIエージェント問わず）が
`docs/03-詳細設計/ステージ/*.md`を開いたとき、各タスクがどのターン（暦日）に
稼働するかを、土日を含む連続した日付列として一望できる。土日はターンとして
存在するが休日出勤カードを使わない限り稼働しないため、その区別が表内で
一目で分かる。

**Why this priority**: ガントチャート表はステージ調整の一次情報源であり
（`CLAUDE.md`のdocs/運用方針）、週モデル変更（Spec-16）後も暦日と稼働実態が
対応しないままだと、調整作業のたびに誤読・誤調整のリスクがある。

**Independent Test**: `docs/03-詳細設計/ステージ/PoCステージ01.md`を開き、
ガントチャート表の列見出しがターン1から締切ターンまで連続した
「ターン番号(曜日)」形式であり、各タスク行のセルが■/・/空欄の3値で
埋まっていることを目視確認できる。

**Acceptance Scenarios**:

1. **Given** PoCステージのガントチャート表, **When** 表の列見出しを確認する,
   **Then** ターン1から締切ターン（30）まで1列も欠けることなく
   「ターン番号(曜日)」形式（例: `1(月)`）で並んでいる
2. **Given** あるタスクの開始ターン・期間, **When** そのタスクの行を確認する,
   **Then** タスク期間内の平日セルは`■`、タスク期間内の土日セルは`・`、
   期間外セルは空欄になっている

---

### User Story 2 - 締切・初期カード・条件付きイベントの表記が実データと一致する (Priority: P2)

Spec-13〜16の変更により`public/data/stages/poc-01.json`の締切・初期カード・
条件付きイベントのターン番号が更新されたが、対応するdocsファイルは
Spec-13時点のまま更新されておらず、実データと乖離していた。この乖離を解消する。

**Why this priority**: docsはグラフDBと並ぶ「人間が読みやすい二重管理」の
位置づけであり（`CLAUDE.md`）、実データと乖離した記述は調整作業を誤らせる。
ガントチャート表記自体の見直し（P1）と同じファイルに対する修正であり、
同一作業内で解消するのが自然。

**Independent Test**: `docs/03-詳細設計/ステージ/PoCステージ01.md`の
ヘッダーテーブル・条件付きイベント表の値を`public/data/stages/poc-01.json`の
実値（`deadline`, `initialCards`, `conditionalEvents[].turn`）と突き合わせ、
すべて一致することを確認できる。

**Acceptance Scenarios**:

1. **Given** `public/data/stages/poc-01.json`の`deadline`が30, **When** docsの
   ヘッダーテーブルを確認する, **Then** 「締切ターン」欄が30と記載されている
2. **Given** `public/data/stages/poc-01.json`の`initialCards`に
   「休出（土）」「休出（日）」が含まれる, **When** docsのヘッダーテーブルを
   確認する, **Then** 「初期カード」欄にこの2枚が含まれている
3. **Given** `public/data/stages/poc-01.json`の`conditionalEvents`の
   ターン番号（5, 12, 16, 22, 24）, **When** docsの条件付きイベント表を
   確認する, **Then** 表のターン番号列がこの5値と一致している

### Edge Cases

- タスクが締切ターンちょうどで終わる場合、最終列（締切ターン列）まで
  セルが正しく埋まること
- 依存タスク待ちで着手が遅れる期間（開始ターン前）は空欄のままであり、
  ■や・が誤って表示されないこと
- 表の横幅がMarkdownとして極端に長くなる（30列以上）ことは許容する
  （`.markdownlint.json`でテーブルは行長チェック対象外のため問題にならない）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ガントチャート表はターン1から当該ステージの締切ターンまでの
  全ターンを1列ずつ、1枚の表として表現しなければならない
- **FR-002**: 各列の見出しは「ターン番号(曜日1文字)」形式（例:
  `1(月)`, `6(土)`, `7(日)`）でなければならない。曜日は月火水木金土日の
  7種を、ターン＝暦日・週の起点は月曜という既存の曜日判定ロジック
  （`src/game/calendar.ts`の`dayOfWeek`）に従って算出しなければならない
- **FR-003**: タスク行の各セルは、タスクの`startTurn`以上
  `startTurn + duration - 1`以下の範囲内かつ平日（土日でない）の場合に
  `■`を表示しなければならない
- **FR-004**: タスク行の各セルは、タスクの期間内かつ土日の場合に`・`を
  表示しなければならない（休日出勤カードを使わない限り稼働しないことを表す）
- **FR-005**: タスク行の各セルは、タスクの期間外（着手前または終了後）の
  場合は空欄でなければならない
- **FR-006**: 表の下に、`■`=平日稼働、`・`=期間内だが土日のため休日出勤
  カードなしには非稼働、という凡例を1行記載しなければならない
- **FR-007**: ヘッダーテーブルの「締切ターン」は`public/data/stages/poc-01.json`
  の`deadline`の値と一致していなければならない
- **FR-008**: ヘッダーテーブルの「初期カード」は`public/data/stages/poc-01.json`
  の`initialCards`の内容と一致していなければならない
- **FR-009**: ヘッダーテーブルは、Spec-13以降実データの参照先が
  `public/data/stages/poc-01.json`に変わったことを反映し、存在しない
  `src/game/stages/poc-01.ts`へのパス参照を含んではならない
- **FR-010**: 条件付きイベント表の「ターン」列は`public/data/stages/poc-01.json`
  の`conditionalEvents[].turn`の値と1件ずつ一致していなければならない
- **FR-011**: 本Specはドキュメント（Markdown）のみを対象とし、
  `src/`配下のゲームロジック・UIには変更を加えてはならない
  （ゲーム内ガントチャートUIはSpec-18の対象）

### Key Entities

- **ステージ設計Markdown**: `docs/03-詳細設計/ステージ/*.md`。ステージごとに
  1ファイル（Spec-13）。ヘッダーテーブル・ガントチャート表・条件付き
  イベント表の3セクションを持つ
- **ガントチャート表**: タスクを行、ターン（暦日）を列とする表。
  セルはタスクのその日の稼働状態（平日稼働／土日非稼働／期間外）を表す

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `docs/03-詳細設計/ステージ/PoCステージ01.md`のガントチャート表を
  見た人が、ソースコードやJSONを確認しなくても、各タスクがどのターン
  （暦日・曜日）に稼働するかを100%正確に読み取れる
- **SC-002**: ヘッダーテーブル・条件付きイベント表の全項目が
  `public/data/stages/poc-01.json`の実値と完全一致する（乖離0件）
- **SC-003**: 表内に存在しないファイルパスへの参照が0件になる

## Assumptions

- 対象ステージは現時点で唯一存在する`poc-01`のみ。将来ステージが追加された
  場合も同じ表記ルールを踏襲する前提とする
- 表の区切り方は1ステージ1表（週ごとの分割は行わない）とする
  （ブレーンストーミングで確認済み）
- 実績・予定の2行表示や稲妻線はゲーム内UI（Spec-18）の担当であり、
  本Specのdocsガントチャート表は「予定（設計時点のスケジュール）」のみを
  表現する
- ターン処理フロー.mdに記載の固定イベント判定（キックオフ等、Spec-16時点で
  未実装）は本Specのスコープ外として変更しない
