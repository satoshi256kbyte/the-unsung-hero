# Feature Specification: ゲーム内ガントチャートUI

**Feature Branch**: `019-in-game-gantt-ui`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "ゲーム内ガントチャートUI: 予定/実績2行＋稲妻線＋依存タスクのPERT的表示を持つガントチャート画面"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - プレイヤーが予定と実績を見比べて進捗の遅れを把握する (Priority: P1)

プレイヤー（PM役）は、メイン画面のメニューから「ガントチャート」画面へ切り替え、
各タスクについて「予定」と「実績」の2行を見比べることで、現在のプロジェクトが
スケジュールに対して進んでいるのか遅れているのかを一目で把握できる。
現在ターンの位置には稲妻線（進捗ライン）が引かれ、稲妻線が予定に対して
どれだけ食い込んでいる／後退しているかで、タスクごとの遅延・前倒しを直感的に読み取れる。

**Why this priority**: 本ゲームの中核は「スケジュール遅延に気づいて手を打つ」判断である。
予定と実績を見比べられる稲妻線付きガントチャートは、その判断を支える一次情報源であり、
これが無いとプレイヤーは遅延の発生に気づけず、適切なカード選択ができない。
ガントチャート画面の価値の大部分はこの表示単独で成立する。

**Independent Test**: ステージ開始後、メニューから「ガントチャート」画面を開き、
各タスク行に予定行・実績行の2行が表示され、現在ターンの列に稲妻線が引かれていることを
確認できる。数ターン進めると、進捗が遅れているタスクでは稲妻線が予定より左側（過去寄り）に
折れ、進んでいるタスクでは右側（未来寄り）に折れることを目視確認できる。

**Acceptance Scenarios**:

1. **Given** ステージ開始直後のガントチャート画面, **When** 画面を開く,
   **Then** 全タスクについて予定行と実績行の2行が表示され、稲妻線が現在ターン（ターン1）の
   位置に垂直に引かれている
2. **Given** あるタスクが予定より進捗が遅れている状態, **When** ガントチャート画面を開く,
   **Then** そのタスクの稲妻線は現在ターン列より過去側（左）に折れて表示される
3. **Given** あるタスクが予定より進捗が進んでいる状態, **When** ガントチャート画面を開く,
   **Then** そのタスクの稲妻線は現在ターン列より未来側（右）に折れて表示される
4. **Given** ガントチャート画面, **When** メニューでメイン画面（ダッシュボード）に戻る操作をする,
   **Then** ダッシュボードに戻り、再度ガントチャート画面を開くと最新の進捗が反映されている

---

### User Story 2 - プレイヤーがタスクの実績（着手・完了の時期）を確認する (Priority: P2)

プレイヤーは各タスクの実績行を見て、そのタスクが実際にいつ着手され、
（完了済みの場合）いつ完了したかを、予定と対比しながら確認できる。
着手が遅れたタスク・想定より長引いているタスクを特定し、次の手を検討する材料にできる。

**Why this priority**: 稲妻線（US1）が「今この瞬間の遅れ」を示すのに対し、
実績行は「これまでの経緯（いつ動き出し、どれだけかかったか）」を示す。
US1だけでも遅延把握はできるが、実績の履歴があると原因分析の精度が上がる。
US1と同じ画面・同じデータ基盤の上に成り立つため、続けて実装するのが自然。

**Independent Test**: タスクを数ターン進めて着手・完了させたあと、
ガントチャート画面の当該タスクの実績行が、実際に着手されたターンから始まり、
完了済みタスクでは完了ターンまで帯が伸びていることを、予定行と対比して確認できる。

**Acceptance Scenarios**:

1. **Given** まだ着手されていないタスク, **When** ガントチャート画面を開く,
   **Then** そのタスクの実績行には帯が表示されない（予定行のみ帯が見える）
2. **Given** 着手済みで進行中のタスク, **When** ガントチャート画面を開く,
   **Then** 実績行の帯が実際の着手ターンから現在ターンまで表示される
3. **Given** 完了済みのタスク, **When** ガントチャート画面を開く,
   **Then** 実績行の帯が着手ターンから完了ターンまで表示され、それ以上伸びない

---

### User Story 3 - プレイヤーがタスクの依存関係（先行タスク）をたどる (Priority: P3)

プレイヤーはガントチャート上でタスクを選択すると、そのタスクが依存している
先行タスク（着手の前提となるタスク）を確認できる。これにより
「どのタスクが片付けば、このタスクを進められるのか」というクリティカルパス的な
情報を、ガントチャート画面内で把握できる（独立したPERT図画面は持たない）。

**Why this priority**: 依存関係の把握は戦略性を高めるが、遅延把握（US1）や
実績確認（US2）に比べると、初期のプレイ判断への影響は小さい。
画面構成上の方針（PERT図は独立ビューを持たず、ガントのタスクから依存をたどる）を
満たすために含めるが、優先度は最後とする。

**Independent Test**: ガントチャート画面で、先行タスクを持つタスクを選択すると、
その先行タスクが視覚的に識別できる（ハイライト・線・一覧など何らかの形で示される）ことを
確認できる。先行タスクを持たないタスクを選択した場合は、依存なしと分かる表示になる。

**Acceptance Scenarios**:

1. **Given** 先行タスクを1つ以上持つタスク, **When** そのタスクを選択する,
   **Then** 依存している先行タスクが視覚的に識別できる形で示される
2. **Given** 先行タスクを持たないタスク, **When** そのタスクを選択する,
   **Then** 依存する先行タスクが無いことが分かる表示になる
3. **Given** あるタスクを選択している状態, **When** 別のタスクを選択する,
   **Then** 依存関係の表示が新しく選択したタスクのものに更新される

---

### Edge Cases

- タスク数が多く画面に収まらない場合、縦スクロール等で全タスクを閲覧できること
- 締切ターンまでの全ターンが横方向に収まらない場合、横スクロール等で全ターンを閲覧できること
- 稲妻線が引かれる現在ターンが締切ターンに達している（最終ターン）場合でも、
  稲妻線と各行が破綻せずに表示されること
- 実績が予定を大きく超過している（予定期間の終端を越えて稼働が続いている）タスクでも、
  実績行が正しく現在ターンまで表示されること
- 依存関係が循環していない前提だが、選択したタスクの先行タスクがさらに先行タスクを持つ
  多段の依存でも、直接の先行タスクが示されれば要件を満たす（多段の自動展開は必須ではない）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、メイン画面のメニューからガントチャート画面へ切り替える操作と、
  ガントチャート画面からメイン画面へ戻る操作を提供しなければならない
- **FR-002**: ガントチャート画面は、各タスクについて「予定」を表す行と「実績」を表す行の
  2行を、タスク単位でまとめて表示しなければならない
- **FR-003**: 予定行は、タスクの計画上の開始時期から計画期間の終了時期までを、
  ターン（暦日）軸に沿った帯として表示しなければならない
- **FR-004**: 実績行は、タスクが実際に着手されたターンから、進行中なら現在ターンまで、
  完了済みなら完了ターンまでを帯として表示しなければならない。未着手のタスクの実績行には
  帯を表示してはならない
- **FR-005**: システムは、各タスクの実績（実際に着手されたターン、および完了したターン）を
  記録・保持し、ガントチャート画面がこれを参照できるようにしなければならない
- **FR-006**: ガントチャート画面は、現在ターンの位置に稲妻線（進捗ライン）を表示しなければ
  ならない。稲妻線は、各タスクの予定に対する実績進捗のずれに応じて、タスク行ごとに
  現在ターン列より過去側（遅れ）または未来側（前倒し）へ折れて表示されなければならない
- **FR-007**: 進捗が予定どおりのタスクでは、稲妻線は現在ターン列の位置（折れ無し）で
  表示されなければならない
- **FR-008**: ガントチャート画面のターン軸（列見出し）は、ターン番号と曜日が識別できる形式で
  表示しなければならない。曜日はゲーム内の既存の曜日判定ロジックに従って算出しなければならない
- **FR-009**: プレイヤーがタスクを選択したとき、システムはそのタスクが依存する先行タスクを
  視覚的に識別できる形で示さなければならない。先行タスクが無い場合は、依存が無いと分かる
  表示にしなければならない
- **FR-010**: 別のタスクを選択したとき、依存関係の表示は新しく選択したタスクのものに
  更新されなければならない
- **FR-011**: タスク数またはターン数が画面に収まらない場合、システムはスクロール等の手段で
  全タスク・全ターンを閲覧可能にしなければならない
- **FR-012**: ガントチャート画面に表示される進捗・実績は、プレイヤーがターンを確定して
  ゲーム状態が更新された後に画面を開いたとき、最新のゲーム状態を反映していなければならない
- **FR-013**: ガントチャート画面はプレイヤーによる直接編集の手段を提供してはならない
  （閲覧専用のビューアーであり、スケジュール変更はカード効果・イベントによってのみ発生する）

### Key Entities *(include if feature involves data)*

- **ガントタスク（予定）**: タスクの計画情報。名称・フェーズ・計画開始時期・計画期間・
  担当メンバー・先行タスク（依存）を持つ。既存のゲーム状態が保持している
- **ガントタスク（実績）**: タスクの実績情報。実際に着手されたターン・完了したターン・
  現在進捗を持つ。予定と対比して稲妻線と実績行の描画に用いる。着手・完了ターンは
  本フィーチャーで新たに記録・保持する対象となる
- **稲妻線（進捗ライン）**: 現在ターンを基準に、各タスクの予定対実績のずれを折れ線として
  表現する視覚要素。ガントチャート画面が現在のゲーム状態から算出する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: プレイヤーは、ガントチャート画面を開いてから5秒以内に、どのタスクが
  予定より遅れているかを（稲妻線の折れ方から）判別できる
- **SC-002**: 遅延・前倒し・予定どおりの3状態のタスクが混在するステージ状況で、
  各タスクの状態を稲妻線の表示から100%正しく読み取れる
- **SC-003**: 完了済み・進行中・未着手の3状態のタスクについて、実績行の帯の有無・長さが
  実際のゲーム状態と100%一致する
- **SC-004**: 任意のタスクを選択したとき、そのタスクの直接の先行タスクが表示に反映される
  （先行タスクの取りこぼし0件、先行タスクが無いタスクでの誤表示0件）
- **SC-005**: メイン画面とガントチャート画面の相互切り替えが、プレイヤーの操作1回で完結する

## Assumptions

- 対象ステージは現時点で唯一存在する `poc-01` を主対象とする。将来ステージが追加されても
  同じ表示ルール（予定/実績2行・稲妻線・依存表示）を踏襲する前提とする
- ターン＝暦日であり、週の起点は月曜という既存の週モデル（Spec-16）・曜日判定ロジックを
  そのまま用いる。土日の非稼働の扱いはガントチャート表示上の色分け等で区別してよいが、
  本フィーチャーの必須要件は予定/実績/稲妻線/依存表示であり、土日の視覚区別は任意とする
- 独立したPERT図画面は持たない。依存関係はガントチャート画面内でタスク選択によりたどる
  （画面構成の既存方針に従う）
- スマートフォン横持ちを前提とした画面領域を想定する（既存の画面設計方針を踏襲）
- 実績の記録（着手ターン・完了ターン）は、既存のターン処理・進捗更新の流れの中で
  ゲーム状態に保持する。稲妻線の折れ量の厳密な算出方式（進捗率ベースか残作業ベースか等）は
  実装計画（plan）で確定する
- リスケカード・仕様追加イベントによる予定の差し替え（既存のガントバリアント差し替え）が
  発生した場合、ガントチャート画面は差し替え後の予定を表示する。実績の連続性の扱いは
  実装計画で確定する

## Dependencies

- **Spec-16（週モデル変更）**: 実装済み。ターン＝暦日・曜日判定ロジックに依存する
- **Spec-17（docsガントチャート表記見直し）**: 実装済み。予定側の表記ルール
  （ターン軸・曜日表記・土日の扱い）の考え方を踏襲する

## Out of Scope

- 独立したPERT図ビュー、EVMビュー、リスクグラフビューの実装（本フィーチャーは
  ガントチャート画面のみを対象とする）
- プレイヤーによるスケジュールの直接編集機能
- 稲妻線を用いた将来予測（見込み完了ターンの外挿表示など）
