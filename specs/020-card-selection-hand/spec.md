# Feature Specification: カード選択・手札への組み込み機能

**Feature Branch**: `020-card-selection-hand`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "カード選択・手札への組み込み機能: ステージ配布プールからターンごとに
手札上限まで補充、配布回数上限カード対応"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - プレイヤーが毎ターン手札を補充されて選択肢を得る (Priority: P1)

プレイヤー（PM役）は、ステージ開始時に一定枚数のカードを手札として受け取り、
以降ターンが進むたびに、ステージごとに定義された配布プールから新しいカードが
手札上限まで補充される。これにより、プレイヤーは毎ターン、その時点の手札から
使うカードを選んでプロジェクトに対応できる。

**Why this priority**: 現状は手札がステージ開始時の固定配列のまま補充されず、
ステージ設計者が初期手札に含めなかったカードはプレイヤーが永久に入手できない
（機能として到達不能）。毎ターンの補充はゲームの中核である「状況に応じたカード選択」を
成立させる前提であり、これが無いとゲームが単調・破綻する。

**Independent Test**: ステージ開始後、手札に初期枚数のカードがあることを確認し、
ターンを確定して次ターンに進むと、手札が上限枚数まで補充される（使ったカードの分だけ
新たに配られる）ことを確認できる。

**Acceptance Scenarios**:

1. **Given** ステージ開始直後, **When** 手札を確認する, **Then** ステージ定義の初期枚数分の
   カードが手札にある
2. **Given** 手札が上限に満たない状態でターンを確定した, **When** 次ターンが始まる,
   **Then** 手札が上限枚数まで配布プールから補充されている
3. **Given** 手札が既に上限枚数ある状態でターンを確定した, **When** 次ターンが始まる,
   **Then** 手札は上限を超えて増えない

---

### User Story 2 - ステージ設計者が配布プールで出現カードを制御する (Priority: P2)

ステージを設計する担当者は、そのステージで配布され得るカードの集合（配布プール）と、
各カードの出やすさ（重み）を定義でき、ステージごとに異なるカード体験を作れる。
プールに含まれないカードは、そのステージでは配布されない。

**Why this priority**: プールによる制御は、ステージごとの難易度・テーマ設計とゲームバランス
（Constitution III の利益率インバリアント）を成立させるために必要。US1（補充の仕組み）が
動くことが前提だが、プール定義はステージ設計の自由度を担保する重要要素。

**Independent Test**: あるステージの配布プールに特定カードのみを定義し、複数ターン進めて
配布されるカードがすべてプール内のカードであること、プール外のカードが配布されないことを
確認できる。

**Acceptance Scenarios**:

1. **Given** 配布プールに含まれるカード集合, **When** 複数ターン補充を受ける, **Then** 補充
   されるカードはすべてプール内のカードである
2. **Given** 出やすさ（重み）に差があるプール, **When** 多数回の配布を統計的に観察する,
   **Then** 重みの大きいカードほど多く配布される傾向がある

---

### User Story 3 - 配布回数に上限のあるカードが上限到達後は配られない (Priority: P3)

一部のカードは「ステージ中に配布される回数の上限」を持ち、その上限に達すると以降の
補充対象から除外される。これにより、強力なカードや特別なカードを「1回限り」など限定的に
配布できる。

**Why this priority**: 基本設計で「ステージ中1回しか配布されないカードもある」と既に方針が
あり、それを実現する。US1・US2に比べると影響範囲は限定的だが、カード設計の表現力を高める。

**Independent Test**: 配布回数上限を1に設定したカードをプールに入れ、複数ターン進めて、
そのカードが最大1回しか配布されず、上限到達後は補充対象から外れることを確認できる。

**Acceptance Scenarios**:

1. **Given** 配布回数上限が1のカード, **When** そのカードが1回配布された後さらにターンを進める,
   **Then** そのカードは以降配布されない
2. **Given** 配布回数上限を持たないカード, **When** 何ターン進めても, **Then** 上限による
   除外は発生しない（プールに存在する限り配布され得る）

---

### Edge Cases

- 配布プールが空、または配布可能なカード（上限未到達）が尽きた場合、補充は行われず、
  手札は現状のまま（上限に満たなくてもエラーにならない）こと
- 手札上限が初期配布枚数より小さい場合でも、初期配布は矛盾なく成立すること
  （初期配布枚数と手札上限はステージ定義で整合させる前提とする）
- ゲーム終了ターン（納期到達・全タスク完了）では補充が行われても手札は使用されないため、
  補充処理がゲーム終了判定を妨げないこと
- 同一カードが手札に複数枚存在してよいか（重複配布の可否）は配布プール定義に従う

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ステージごとに「配布プール」（配布され得るカードの集合と、
  各カードの出やすさを表す重み）を定義できなければならない
- **FR-002**: システムは、ステージ開始時に、ステージ定義の初期枚数のカードを手札に配布
  しなければならない
- **FR-003**: システムは、各ターンの開始時（前ターン確定後の次ターン開始時）に、手札が
  手札上限に満たない場合、配布プールから不足分を補充しなければならない
- **FR-004**: システムは、手札上限を超えて手札を増やしてはならない
- **FR-005**: 補充で配布されるカードは、必ず当該ステージの配布プールに含まれるカードで
  なければならない。プールに含まれないカードを配布してはならない
- **FR-006**: システムは、配布プールの各カードの重みに応じて配布確率を決定しなければならない
  （重みが大きいほど配布されやすい）
- **FR-007**: システムは、カードごとに「ステージ中の配布回数上限」を任意で定義できなければ
  ならない。上限が定義されたカードは、配布回数がその上限に達したら以降の補充対象から
  除外しなければならない
- **FR-008**: 配布回数上限を持たないカードは、配布回数による除外を受けてはならない
- **FR-009**: 配布可能なカード（プールに存在し、かつ配布回数上限に未到達）が存在しない場合、
  システムは補充を行わず、手札を現状のまま保たなければならない（エラーとしない）
- **FR-010**: 手札の補充・配布はステージ進行中に一貫した規則で行われ、プレイヤーは補充後の
  手札から従来どおりカードを選択・使用できなければならない
- **FR-011**: 本機能は既存のカード選択・使用（コスト上限内での配置、対象選択など）の挙動を
  壊してはならない。手札の構成方法（固定→補充）のみを変更する

### Key Entities *(include if feature involves data)*

- **配布プール**: ステージごとに定義される、配布され得るカードの集合。各カードに出やすさ
  （重み）と、任意で配布回数上限を持つ
- **手札**: プレイヤーが現在保持しているカードの集合。上限枚数を持ち、ターンごとに配布
  プールから補充される
- **配布回数の記録**: ステージ進行中に各カードが配布された累計回数。配布回数上限との比較に
  用いる（ゲーム状態として進行中に保持する）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ステージ設計者が初期手札に含めなかったカードでも、配布プールに入れれば
  プレイヤーがゲーム中に入手できる（到達不能なカードが0件になる）
- **SC-002**: 手札上限を超える枚数が手札に存在する状況が、ゲーム進行中に一度も発生しない
- **SC-003**: 配布回数上限が N のカードは、1ステージのプレイを通じて最大 N 回しか配布されない
- **SC-004**: 補充されるカードが配布プール外である事象が、ゲーム進行中に一度も発生しない
- **SC-005**: 既存のカード選択・使用・ターン確定の一連の操作が、本機能導入後も従来どおり
  完了できる（回帰なし）

## Assumptions

- 対象ステージは現時点で唯一存在する `poc-01` を主対象とする。将来ステージが追加されても
  同じ配布ルール（プール・重み・配布回数上限・手札上限）を踏襲する前提とする
- 配布はランダム性を伴う。乱数の具体的な実装方式（既存の進捗ダイス等と同じ仕組みを使うか）は
  実装計画（plan）で確定する
- 手札上限・初期配布枚数の具体的な数値、および poc-01 の配布プール内容（どのカードを
  どの重みで含めるか）はバランス調整の対象であり、plan 以降で確定する
  （基本設計「8コスト分のカード枠」との整合も plan で確認する）
- 既存の暫定対応（休出（土）（日）を initialCards に静的追加、ADR-026）は、本機能導入後は
  配布プール経由での入手に置き換えられる想定。置き換えの要否・移行方法は plan で確定する
- カードの重複配布（同一カードが手札に複数枚）を許すかはステージ定義に委ねる。既定の扱いは
  plan で確定する

## Dependencies

- 既存のカードシステム（27種のカード定義、`state.hand`、カード選択・使用・ターン処理）に
  依存する。本機能は手札の構成方法を「固定配列」から「プールからの補充」に変更する
- ADR-026（Spec-16 で initialCards への静的追加による暫定対応を行い、恒久対応を本 Spec に
  バックログ化した経緯）を前提とする

## Out of Scope

- 山札（デッキ）を積んでドロー・捨て札で循環させる本格的なデッキビルド機構
- カードの獲得をイベントや実績に連動させる仕組み（配布はプールからのランダム補充に限る）
- 手札のマリガン（引き直し）やプレイヤーによる能動的なドロー操作
- カードのレアリティ・アンロック・永続的なコレクション要素
